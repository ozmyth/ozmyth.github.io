Why DiffRay

文本 diff 的噪音，不该是你的负担

典型的 diff 工具把 JSON 当字符串逐行对比，时间戳、ID、字段顺序的微小变动都会刷屏。DiffRay 引入结构化模型，只关心"语义上到底变没变"。

🔕

忽略噪音字段

生成的时间戳、调试字段、请求 ID，比较前直接排除，结果只剩真正重要的变化。

🧠

字段级比较规则

同一个 payload 里，年龄走范围校验、邮箱走正则、姓名走大小写不敏感，各走各的。

🏷️

严重程度分级

每个路径绑定 Critical / Warning 等级，一眼区分致命差异和可接受的等价写法。

🧰

预处理转换

字符串里嵌套的 JSON、需要排序的数组、要统一的大小写——比之前先规范化。

🔌

插件与 Lua 扩展

没有覆盖到的规则？写几行 Lua 或挂一个 .so 插件，不用改引擎代码。

🧪

浏览器试玩

仓库自带 Web UI，左右贴 JSON、配规则、看判定，不用先写一行 Go。

01

Configuration

一份配置，定义全部规则

比较器与转换规则写在同一个 FullConfig 里，JSON / YAML 均可。

# 字段级比较规则
comparators:
  - path: $.user.name
    type: lua
    config:
      script: |
        function compare(old, new, ctx)
          return {
            matched = string.lower(old) == string.lower(new),
            reason   = "case-insensitive comparison"
          }
        end
  - path: $.user.age
    type: range
    config: { min: 18, max: 120 }

# 比较前预处理
transform:
  rules:
    - type: exclude
      config:
        path: [$.metadata.created, $.debug]
    - type: parseJsonString
      config: { path: $.response.body }
{
  "comparators": [
    {
      "path": "$.user.name",
      "type": "lua",
      "config": {
        "script": "function compare(old, new, ctx) return { matched = string.lower(old) == string.lower(new) } end"
      }
    },
    {
      "path": "$.user.age",
      "type": "range",
      "config": { "min": 18, "max": 120 }
    }
  ],
  "transform": {

      { "type": "exclude", "config": { "path": ["$.metadata.created", "$.debug"] } },
      { "type": "parseJsonString", "config": { "path": "$.response.body" } }

Lua & Plugin Extension

比较与转换，都能用 Lua 和插件写出来

Lua 是 DiffRay 的一等公民。同时，插件系统让你用 Go 编写原生扩展，两者互为补充。

comparator Lua Comparator

在指定 JSONPath 上执行脚本，判定两个值是否等价。

  1. 注入全局变量：old / new / ctx / config / path
  2. 沙箱中执行脚本
  3. 返回 bool 或 {matched, reason} 表
  4. 类型不符 → 报错并标记不匹配
function compare(old, new, ctx)
  return {
    matched = string.lower(old) == string.lower(new),
    reason  = "case-insensitive comparison"
  }
end

processor Lua Processor

对路径匹配到的每个节点执行脚本，返回值写回原路径。

  1. 按路径匹配所有节点（支持通配）
  2. 逐节点注入 doc 与 path
  3. return 有效值写回；return nil 跳过
  4. 包裹在作用域内执行，便于追踪
-- doc 为当前节点值，path 为节点路径
if doc < 0 then return nil end  -- 跳过负值
return doc + 1

plugin Plugin 系统

用 Go 编写原生扩展，编译为 .so 或通过 built-in 注册，获得完整类型安全与性能。

  1. 实现 PluginEntry() 函数，返回元数据与 Onload 钩子
  2. 在 Onload 中通过 PluginHost 注册比较器、处理器、导出器
  3. 支持 .so 动态加载（Linux/macOS）或进程内 built-in 注册
  4. 插件与 Lua 脚本可混用，互为补充
func PluginEntry() *plugin.PluginEntry {
  return &plugin.PluginEntry{
    Meta: plugin.PluginMeta{
      Name:    "uuid_comparator",
      Version: "1.0.0",
    },
    Onload: func(host *plugin.PluginHost) error {
      host.RegisterComparator(&UUIDComparator{})
      return nil
    },
  }
}

manager Plugin Manager

PluginManager 负责插件的生命周期管理，支持动态加载、卸载和热重载。

  1. Load(soPath) 从 .so 文件加载并初始化插件
  2. Unload(soPath) 卸载指定插件
  3. RegisterBuiltin(entry) 注册进程内 built-in 插件
  4. 插件 API 定义在 pkg/plugin/api.go
pm := plugin.NewPluginManager()
err := pm.Load("./plugins/uuid.so")
if err != nil {
  log.Fatal(err)
}
// 注册 built-in 插件
pm.RegisterBuiltin(myPluginEntry)
Workflow

典型使用五步走

准备输入

准备 old / new 两份 JSON 负载。

排除噪音

用 exclude 等规则丢掉无关字段。

绑定规则

为关键路径挂比较器。

运行 diff

执行并拿到结构化结果。

审视结果

区分真实差异与等价匹配。

HTTP API

三个接口，接入任何系统

POST /api/diff

提交 old、new 与可选 config，返回差异、等价项、忽略项与严重程度摘要。

POST /api/validate

校验配置结构合法性，规则写错之前先拦下来。

GET /health

健康检查端点，配合网关与编排系统使用。
